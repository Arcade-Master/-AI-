# 05｜SFT、偏好对齐（RLHF/DPO/GRPO）、PEFT、遗忘、RLAIF

**建议阅读顺序（本篇内部）**：**SFT 在优化什么、mask 怎么画** → **teacher forcing / 训练目标与推理分布**（和 exposure bias、RL 的关系）→ **LoRA 等 PEFT** → **RLHF 数据与目标（RM + PPO）** → **DPO：偏好数据怎么来、loss 每一项在干什么、和在线 RL 的本质差别** → **GRPO：和 PPO 差在哪、优势从哪来**（逐步计算见 **`12`**）→ **RLAIF：AI 裁判介入点、数据流、后面接什么 loss** → **灾难性遗忘**。  
**PPO/GRPO 的逐步计算、GAE、REINFORCE 细节** 见 **`12`**；本篇把 **「和 SFT 怎么衔接 + 面试能展开讲」** 说满。

## 1. SFT：到底在对哪些 token 算 loss

**目标**：在 (指令, 回答) 或对话里，提高 **人类希望模型说出来的那部分** 的似然。

**常见 mask**：只对 **assistant / 模型应答段** 算交叉熵；**user / system** 往往 **loss=0**。原因：不想用大量梯度教模型 **复述用户**，而把容量用在 **「怎么答」** 上。

**label shift（右移）**：自回归是「看过去预测下一个」，实现里 logits 与 labels **常错位一位**；和 `ignore_index` 一起用，避免 off-by-one。

### 1.1 Teacher forcing：训练在优化的数学对象是什么

**自回归最大似然（一步一 token）** 的标准目标是对每个位置 t：

```
- log π_θ(y_t | x, y_<t)
```

**Teacher forcing（TF）**：在算 `y_t` 的条件时，历史 `y_<t` 用 **数据里的真值 token**，而不是模型自己上一步的预测。

- **好处**：整条序列的 teacher 信号 **已知**，可 **并行** 算所有位置；梯度稳定，实现简单。  
- **和推理的裂口**：推理时条件是 **模型自己采样的前缀**，分布 ≠ 训练时「永远走真轨」。前缀一旦错，后面条件分布整体偏移 → **exposure bias（暴露偏差）**。  
- **缓解思路（面试可点名）**：**Scheduled sampling**（一定概率用模型上一步代替 teacher）、**Word dropout**、**Seq2Seq 里用 beam 暴露噪声前缀**、以及 **用 RL 在「自己生成的前缀」上直接优化期望回报**（on-policy 对齐）。

**怎么答成「懂原理」**：「SFT 的 MLE 在 TF 下等价于在 **真前缀** 上最大化下一步似然；推理是 **自条件** 的马尔可夫链，训练目标与 rollout 目标不一致，所以长生成会累积误差；RL 类方法把优化对象改成 **整条生成轨迹上的期望**。」

### 面试怎么答（短版）

「SFT 只对回答段算 CE；instruction 段 mask；TF 稳定但和推理分布不一致，长输出要警惕 exposure bias。」

## 2. RLHF：数据怎么建、loss 怎么接、和「只有 SFT」差在哪

**典型三阶段（OpenAI/InstructGPT 叙事）**：

1. **SFT**：行为克隆，得到 `π_SFT`。  
2. **奖励模型 RM**：收集 **同一 prompt 下成对回答 (y_w, y_l)**（人标谁更好）。RM `r_φ(x,y)` 常用 **Bradley–Terry / pairwise ranking** 思想训练，使 `r(x,y_w) > r(x,y_l)`，loss 形态接近 **对比 / margin / logistic**，本质是 **学一个标量打分器**，不是生成模型。  
3. **强化学习微调策略 `π_θ`**（常从 SFT 初始化）：最大化  
   `E[ r_φ(x,y) - β · KL( π_θ(·|x) ‖ π_ref(·|x) ) ]`  
   其中 `π_ref` 常为冻结的 SFT，用来 **防止为了骗 RM 而跑飞语言**。**PPO** 里：用 **critic `V`** 估优势、**clip 比率** 限制每步策略变化、可能再加 **熵 bonus**。

**和 SFT 的本质差别**：SFT 是 **「给定人类写的一条 y，拉高它的 log p」**；RLHF 是 **「在整个生成空间里，按 RM 的期望回报选轨迹」**，允许 **探索**、**多步 credit**、以及 **对 RM 定义的细粒度行为**（如有帮助、更诚实）优化，但 **工程重、方差大、要防 reward hacking**。

### 面试怎么答

「RLHF = 偏好数据训 RM + PPO 在 RM 回报下更新生成策略，并用 KL 锚住参考模型；比 SFT 更贴『偏好』但系统复杂。」

## 3. DPO：偏好数据、参考模型、loss 每一项、和 PPO 系的分界线

**动机**：PPO 要 **在线从当前 `π_θ` 采样**、维护 **value**、多进程 rollout；DPO 想 **用静态偏好数据集做离线更新**，把问题收成 **带参考模型的分类式损失**。

**数据**：与 RM 阶段类似，需要 **(x, y_w, y_l)**，`y_w` 为「胜」、`y_l` 为「负」。来源可以是人标，也可以是 **RLAIF**（见第 5 节）造出来。

**参考模型 `π_ref`**：通常取 **冻结的 SFT**（或 SFT 一步前的 checkpoint）。DPO 推导里隐含 **奖励重写**：在 BT 模型下可把奖励表达成 **策略与参考的对数似然差**（差一个配分函数也没关系，因为成对比较会消掉公共部分）。**直觉**：「模型相对参考，更愿给 `y_w` 多高概率、更不愿给 `y_l` 多高概率」。

**常用 DPO 损失（记「隐式奖励 = log 策略 − log 参考」的差分）**：对每个偏好对最小化

```
- log σ( β · ( (log π_θ(y_w|x) - log π_ref(y_w|x)) - (log π_θ(y_l|x) - log π_ref(y_l|x)) ) )
```

括号内等于 **「胜者在隐式奖励上比负者高多少」**；`σ` 为 logistic。实现里常写 **`-log σ( ... )`**。其中：

- **`log π_θ(y_w) - log π_ref(y_w)`**（负者同理）：单条回答在 **相对参考** 下的「偏好势能」；两项相减才是 **成对** 可比量。  
- **`β`**：放大/缩小该势能差；越大越 **听偏好**、但更易 **过拟合噪声 / 压离参考**；过小则几乎不动。

**和 RLHF+PPO 的对比（面试必说清）**：

| 维度 | RLHF + PPO | DPO |
|------|------------|-----|
| 是否需要在线采样 | 需要（从 `π_θ` rollout） | **不需要**；数据里已有 `y_w,y_l` |
| 价值函数 / GAE | 要 | **不要** |
| RM | 显式训 `r_φ` | **不显式训 RM**；偏好进 **一条 loss** |
| 优化稳定性 | 调参面大 | 通常 **更轻**，但依赖 **偏好对与参考** 质量 |
| 失败模式 | reward hacking、模式塌 | **标注噪声、参考选错、β 不当**、长链推理上成对偏好是否充分 |

**数据质量敏感点**：同一 `x` 下若 `y_w` 并不比 `y_l` 真的好、或两者几乎一样好，DPO 仍在硬推 margin → **学歪**；长回答只标整体偏好时，**credit 不知给哪一段**，和 RL 里 dense reward 设计是同一类难题。

### 面试怎么答

「DPO 用 (x,y_w,y_l) 和冻结 `π_ref` 直接优化策略，loss 是 sigmoid 包住 **当前与参考的对数似然比之差**；省掉 PPO 环和显式 RM，但成对标注与 β、参考模型绑定决定上限。」

## 4. GRPO：和 PPO 差在哪（原理一句话 + 衔接 12）

**设定**：对同一 prompt `x` **一次采 G 条**完整回答 `{y_i}_{i=1..G}`，每条算标量回报 `R_i`（可来自执行单测、数学 verifier、格式分、RM 等）。

**核心**：不主要依赖 **学出来的 `V(s)`**，而用 **组内统计量** 当 baseline，例如  
`A_i = (R_i - mean({R})) / std({R})`（或只用减均值、或排名替代）。

**策略梯度形态**：在 `π_θ` 上对 **整条 y_i** 的 log-prob（常 sum over tokens）乘 `A_i` 做上升步，并通常 **仍加 KL 到参考**，防止为刷分乱码。

**和 PPO 关系**：PPO 用 **GAE + clip** 精细控 **逐步** credit；GRPO 用 **「同 prompt 多答案」互相当基线**，适合 **可自动验分** 的任务，**弱化 critic**。逐步公式与实现坑见 **`12`**。

### 面试怎么答

「GRPO = 同 prompt 多样本 + 组内中心化/标准化回报当优势；省 critic、吃可验证奖励；和 PPO 比更粗粒度但在代码数学上好用。」

## 5. RLAIF：AI 在哪一步介入、产出什么、后面 loss 怎么接

**定义**：**用强模型（或规则+模型管线）代替人类** 生产 **偏好信号**，再接 **与 RLHF 相同或更轻的后端**。

**典型数据流**：

1. **采样**：用当前或 SFT 策略对 prompt 集生成 **多条候选**（或强模型直接写候选）。  
2. **裁判**：强 LLM 读 `(x, y_a, y_b)` 输出 **谁更好** / 打分；或用 **程序验证**（通过率）+ LLM 综合。产出仍是 **`(x, y_w, y_l)` 或标量分`**。  
3. **下游二选一（面试要说清分支）**：  
   - **A. 仍训 RM + PPO**：偏好对用来训 `r_φ`（pairwise logistic），后面与 RLHF **完全同构**；此时「AI 介入」在 **标注替代人**。  
   - **B. 直接 DPO / IPO 等**：偏好对 **跳过显式 RM**，进 DPO loss；「AI 介入」在 **造 y_w,y_l**。  
4. **没有魔法第三种 loss**：RLAIF 不是新目标函数，而是 **偏好数据的自动化来源**；**loss 仍是 RM 分类 / PPO / DPO** 之一。

**Reward 从哪来**：若走 PPO，`reward = r_φ` 或 `R_verifier` 组合；若走 DPO，**不显式标量 reward**，偏好已编码在 **成对 log-ratio loss** 里。

**风险（要能答）**：裁判 **系统性偏见**（例如偏爱长文、某种格式）会被放大；与人标混合、**held-out 人评**、**拒绝采样低置信对** 是常见工程补丁。

### 面试怎么答

「RLAIF = 用强模型批量产偏好对或打分；后面要么训 RM+PPO，要么直接 DPO；要说明 AI 在标注侧，loss 侧没有单独叫 RLAIF 的式子。」

---

## 6. LoRA：低秩为什么常常够用

大矩阵的有效微调更新，经验上 **秩不高**；显式 `ΔW = B A` 把搜索空间 **限制在低维流形**，**冻结主干** → **省显存（少存优化器状态）**、**少动语言能力**。rank 靠 dev 扫，不是玄学常数。

---

## 7. 灾难性遗忘

**现象**：强训某域后 **通用能力掉**。  
**原因**：小数据大步更新把表示 **拉进窄流形**。  
**缓解**：混合通用数据、小 lr、早停、KL 到参考、replay、LoRA 限自由度；评测 **别只看新域**。

### 面试怎么答

「遗忘是表示漂移；LoRA 不是免死金牌，只是少改底座。」

---

## 本篇小结

- SFT = **TF 下的逐步 CE**；与推理 **分布错位** → exposure bias。  
- RLHF = **RM（成对偏好）+ PPO（KL 约束）**；DPO = **(y_w,y_l)+π_ref 的成对 sigmoid loss**，**离线**、无 value。  
- GRPO = **组内相对回报当优势**，接 **`12`** 展开。  
- RLAIF = **偏好数据来源**；**loss 仍是 RM/PPO/DPO 家族**。
