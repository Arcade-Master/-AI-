## 1. SFT：到底在对哪些 token 算 loss

**目标**：在 (指令, 回答) 或对话里，提高 **人类希望模型说出来的那部分** 的似然。

**常见 mask**：只对 **assistant / 模型应答段** 算交叉熵；**user / system** 往往 **loss=0**。原因：不想用大量梯度教模型 **复述用户**，而把容量用在 **「怎么答」** 上。

**label shift（右移）**：自回归是「看过去预测下一个」，实现里 logits 与 labels **常错位一位**；和 `ignore_index` 一起用，避免 off-by-one。

### 1.1 Teacher forcing：训练在优化的数学对象是什么

**自回归最大似然（一步一 token）** 的标准目标是对每个位置 t：

```
- log π_θ(y_t | x, y_<t)
```

整句写法（便于回忆和 CE 的关系）：

```
log π_θ(y_{1:T}|x) = Σ_{t=1..T} log π_θ(y_t | x, y_<t)
L_SFT = - Σ_t log π_θ(y_t | x, y_<t)   （再对 batch 取平均）
```

**Teacher forcing（TF）**：在算 `y_t` 的条件时，历史 `y_<t` 用 **数据里的真值 token**，而不是模型自己上一步的预测。

- **好处**：整条序列的 teacher 信号 **已知**，可 **并行** 算所有位置；梯度稳定，实现简单。  
- **和推理的裂口**：推理时条件是 **模型自己采样的前缀**，分布 ≠ 训练时「永远走真轨」。前缀一旦错，后面条件分布整体偏移 → **exposure bias（暴露偏差）**。  
- **缓解思路（面试可点名）**：**Scheduled sampling**（一定概率用模型上一步代替 teacher）、**Word dropout**、**Seq2Seq 里用 beam 暴露噪声前缀**、以及 **用 RL 在「自己生成的前缀」上直接优化期望回报**（on-policy 对齐）。

**TF 与推理的裂口**：训练用真前缀，推理用自采样前缀，分布不一致，长输出易累积误差（exposure bias）。RL 把优化对象从「单步似然」改成「整条轨迹期望回报」，可缓解。

**面试口述**：「SFT 只对回答段算 CE，TF 稳定但与自回归推理分布错位；长生成要警惕 exposure bias。」

## 2. RLHF：数据怎么建、loss 怎么接、和「只有 SFT」差在哪

**典型三阶段（OpenAI/InstructGPT 叙事）**：

1. **SFT**：行为克隆，得到 `π_SFT`。
2. **奖励模型 RM**：收集 **同一 prompt 下成对回答 (y_w, y_l)**（人标谁更好）。RM `r_φ(x,y)` 常用 **Bradley–Terry / pairwise ranking** 思想训练，使 `r(x,y_w) > r(x,y_l)`，loss 形态接近 **对比 / margin / logistic**，本质是 **学一个标量打分器**，不是生成模型。
3. **强化学习微调策略 `π_θ`**（常从 SFT 初始化）：最大化
  `E[ r_φ(x,y) - β · KL( π_θ(·|x) ‖ π_ref(·|x) ) ]`  
   其中 `π_ref` 常为冻结的 SFT，用来 **防止为了骗 RM 而跑飞语言**。**PPO** 里：用 **critic `V`** 估优势、**clip 比率** 限制每步策略变化、可能再加 **熵 bonus**。

**和 SFT 的本质差别**：SFT 是 **「给定人类写的一条 y，拉高它的 log p」**；RLHF 是 **「在整个生成空间里，按 RM 的期望回报选轨迹」**，允许 **探索**、**多步 credit**、以及 **对 RM 定义的细粒度行为**（如有帮助、更诚实）优化，但 **工程重、方差大、要防 reward hacking**。

### 2.1 RM 打分、Value 模型训练与 GAE（PPO 里的 critic 部分）

**RM（奖励模型）打分对象**：在经典 RLHF 里，RM 是在**同一 prompt 下的一整条生成 y** 上打一个标量分（`r(x, y)`），而不是对每一步 token 打分。训练 RM 用的是成对偏好 `(y_w, y_l)`，目标是让 RM 给胜者更高分。实际 RL 阶段，reward 通常是**稀疏**的（生成结束时才给一次分），不是每一步都有。想做「过程奖励」（每一步或每几步打分）需要专门的 Process Reward Model (PRM)，不是默认的 RM。

**Value 模型（Critic）训练**：Value 模型的目标是预测「从当前状态 s_t 出发，按当前策略继续生成，预期能拿到多少总回报」。

1. **工程复杂度高**：要同时训 policy + value（critic），还要调 `clip`、value loss 权重、KL、熵系数、reward whitening 等，系统耦合重。
2. **value 学偏会误导策略**：LLM 场景奖励稀疏、长序列 credit 难，`V` 估错会把 `A_t` 带偏，训练不稳。
3. **离线偏好方法替代**：DPO/IPO/KTO 这类直接用偏好对优化，不需要在线 rollout + critic + GAE。
4. **可验证任务里有更简单基线**：如 GRPO 用同 prompt 多样本的组内统计做优势近似，少一个 value 网络，调参面小。

不是“PPO/GAE 过时”，而是**在 LLM 对齐里常因成本与稳定性被更轻方法替代**；有些高价值任务仍会用 PPO/GAE。

### 面试怎么答

「RLHF = 偏好数据训 RM + PPO 在 RM 回报下更新生成策略，并用 KL 锚住参考模型；比 SFT 更贴『偏好』但系统复杂。」

## 3. DPO：偏好数据、参考模型、loss 每一项、和 PPO 系的分界线

**动机**：PPO 要 **在线从当前 `π_θ` 采样**、维护 **value**、多进程 rollout；DPO 想 **用静态偏好数据集做离线更新**，把问题收成 **带参考模型的分类式损失**。

**数据**：与 RM 阶段类似，需要 **(x, y_w, y_l)**，`y_w` 为「胜」、`y_l` 为「负」。来源可以是人标，也可以是 **RLAIF**（见第 5 节）造出来。

**参考模型 `π_ref`**：通常取 **冻结的 SFT**（或 SFT 一步前的 checkpoint）。DPO 推导里隐含 **奖励重写**：在 BT 模型下可把奖励表达成 **策略与参考的对数似然差**（差一个配分函数也没关系，因为成对比较会消掉公共部分）。**直觉**：「模型相对参考，更愿给 `y_w` 多高概率、更不愿给 `y_l` 多高概率」。

**常用 DPO 损失（记「隐式奖励 = log 策略 − log 参考」的差分）**：对每个偏好对最小化

```
- log σ( β · ( (log π_θ(y_w|x) - log π_ref(y_w|x)) - (log π_θ(y_l|x) - log π_ref(y_l|x)) ) )
```

括号内等于 **「胜者在隐式奖励上比负者高多少」**；`σ` 为 logistic。实现里常写 `**-log σ( ... )`**。其中：

- `**log π_θ(y_w) - log π_ref(y_w)`**（负者同理）：单条回答在 **相对参考** 下的「偏好势能」；两项相减才是 **成对** 可比量。  
- `**β`**：放大/缩小该势能差；越大越 **听偏好**、但更易 **过拟合噪声 / 压离参考**；过小则几乎不动。

**和 RLHF+PPO 的对比（面试必说清）**：


| 维度         | RLHF + PPO          | DPO                              |
| ---------- | ------------------- | -------------------------------- |
| 是否需要在线采样   | 需要（从 `π_θ` rollout） | **不需要**；数据里已有 `y_w,y_l`          |
| 价值函数 / GAE | 要                   | **不要**                           |
| RM         | 显式训 `r_φ`           | **不显式训 RM**；偏好进 **一条 loss**      |
| 优化稳定性      | 调参面大                | 通常 **更轻**，但依赖 **偏好对与参考** 质量      |
| 失败模式       | reward hacking、模式塌  | **标注噪声、参考选错、β 不当**、长链推理上成对偏好是否充分 |


**数据质量敏感点**：同一 `x` 下若 `y_w` 并不比 `y_l` 真的好、或两者几乎一样好，DPO 仍在硬推 margin → **学歪**；长回答只标整体偏好时，**credit 不知给哪一段**，和 RL 里 dense reward 设计是同一类难题。

### 面试怎么答

「DPO 用 (x,y_w,y_l) 和冻结 `π_ref` 直接优化策略，loss 是 sigmoid 包住 **当前与参考的对数似然比之差**；省掉 PPO 环和显式 RM，但成对标注与 β、参考模型绑定决定上限。」

## 4. GRPO：和 PPO 差在哪（原理一句话 + 衔接 12）

**设定**：对同一 prompt `x` **一次采 G 条**完整回答 `{y_i}_{i=1..G}`，每条算标量回报 `R_i`（可来自执行单测、数学 verifier、格式分、RM 等）。

**核心**：不主要依赖 **学出来的 `V(s)`**，而用 **组内统计量** 当 baseline，例如  
`A_i = (R_i - mean({R})) / std({R})`（或只用减均值、或排名替代）。

**策略梯度形态**：在 `π_θ` 上对 **整条 `y_i`** 的 log-prob（常 sum over tokens）乘 `A_i` 做上升步，并通常 **仍加 KL 到参考**，防止为刷分乱码。

**和 PPO 关系**：PPO 用 **GAE + clip** 精细控 **逐步** credit；GRPO 用 **「同 prompt 多答案」互相当基线**，适合 **可自动验分** 的任务，**弱化 critic**。逐步公式与实现坑见 `**12` §5**。

### 面试怎么答

「GRPO = 同 prompt 多样本 + 组内中心化/标准化回报当优势；省 critic、吃可验证奖励；和 PPO 比更粗粒度但在代码数学上好用。」

## 4.1 GSPO、DAPO、VAPO：相对 GRPO 优化什么

下面按 **「和 GRPO 差在哪」** 记；**GSPO** 在长序列推理 RL 里近年面试权重高，建议与 `**12` §7～§8** 对照背诵。

### GSPO（Group Sequence Policy Optimization）

**问题从哪来**：GRPO/PPO 常在 **token 级** 算 importance ratio `r_t = π_θ/π_old`，长回答时 **每个 token 一个比率**，噪声沿序列 **累加**，训练方差大、长序列尤其不稳（Qwen 团队 GSPO 论文的核心动机之一）。

**Group 采样**：与 GRPO 一样，对同一 prompt `x` 采 **一组（G 条）完整序列** `{y_i}`，用 **组内均值/方差** 做 baseline 降方差——**Group 结构保留**。

**关键改动（相对 GRPO）**：把 **clip、reward、策略梯度上的 importance 权重** 收到 **序列级**——用整条序列似然的几何平均构造 **序列比率** `s_i(θ)`（等价于对 log-ratio 按长度归一），在 **序列粒度** 做 PPO 式 clip 与优化，避免 token 级比率在长链上 **方差爆炸**。

**Group Size（G）对收敛**：

- **G 太小**：组内 baseline 噪声大，优势估计抖，收敛慢或不稳。  
- **G 适中增大**：组均值更稳，**方差降、收敛常更快**；但 **采样与 rollout 成本线性涨**。  
- **G 过大**：边际收益递减，且若组内奖励全相同（全对/全错），**梯度几乎为 0**（DAPO 的 dynamic sampling 专门治这类无效组）。

**相对 DPO 的优化点（别混成一类算法）**：


| 维度  | DPO                   | GSPO（及 GRPO 系）                 |
| --- | --------------------- | ------------------------------ |
| 数据  | 离线偏好对 `(x, y_w, y_l)` | **在线**从当前 `π_θ` 采样多条完整回答       |
| 目标  | 隐式奖励的 **成对分类** loss   | **策略梯度** + 可验证/模型奖励            |
| 长序列 | 不直接处理 rollout 方差      | **序列级 ratio** 针对 **长输出 RL 方差** |
| 适用  | 对齐偏好、省 rollout        | 数学/代码等 **可打分** 推理强化            |


面试一句：**「DPO 是离线偏好分类；GSPO 是在 GRPO 的组采样思路上，把 importance 从 token 收到 sequence，专治长链 RL 方差。」**

### DAPO（Decoupled Clip and Dynamic sAmpling Policy Optimization）

在 **GRPO 骨架** 上常见增强（阿里 / NeMo 等实现口径）：

- **Clip-Higher**：`ε_low ≠ ε_high` 的非对称 clip，避免「好 token」过早被 clip 封顶。  
- **Dynamic Sampling**：只保留 **组内奖励有方差** 的 prompt（如 `std(R_i)>0`），跳过 **全对/全错** 的无效组，提高有效梯度占比。  
- **Token-Level Loss 权重**、**过长回答的 reward shaping**：缓解 **异长序列** 与截断噪声。

相对 GRPO：**更稳、更少算力浪费在零梯度组**；工程调参项更多。

### VAPO（Value-model-based Augmented PPO）

走 **另一条路**：**不扔掉 value**，而是 **把 value 训准、用对**（Qwen 32B + AIME 等报告里常见叙事）。

相对 **无 critic 的 GRPO/DAPO**，VAPO 强调：

- **Value-Pretraining**、**Decoupled-GAE**、**Length-Adaptive GAE**：缓解 **价值网络偏差** 与 **长短序列混杂** 带来的优势估计失真。  
- 仍可有 **Group Sampling**、**Clip-Higher**、**Token-Level PG** 等与 GRPO 系 **组件级重叠**，但 **优势来源** 常回到 **GAE + V**，而不是纯组内减均值。

**选型口径**：要 **极简、可验证奖励、少维护 critic** 就选 GRPO/DAPO/GSPO 一脉；要 **复杂推理、愿训 value、追求样本效率与稳定性** 就看 VAPO 类 value-augmented 方案。

### 面试怎么答

「GRPO 用组内 baseline 省 critic；DAPO 加动态采样和非对称 clip 提效；GSPO 把 importance 收到序列级降长链方差；VAPO 反过来加强 value/GAE。DPO 是离线偏好，和它们在线 RL 不是一条线。」

## 5. RLAIF：AI 在哪一步介入、产出什么、后面 loss 怎么接

**定义**：**用强模型（或规则+模型管线）代替人类** 生产 **偏好信号**，再接 **与 RLHF 相同或更轻的后端**。

**典型数据流**：

1. **采样**：用当前或 SFT 策略对 prompt 集生成 **多条候选**（或强模型直接写候选）。
2. **裁判**：强 LLM 读 `(x, y_a, y_b)` 输出 **谁更好** / 打分；或用 **程序验证**（通过率）+ LLM 综合。产出仍是 `**(x, y_w, y_l)` 或标量分`**。
3. **下游二选一（面试要说清分支）**：
  - **A. 仍训 RM + PPO**：偏好对用来训 `r_φ`（pairwise logistic），后面与 RLHF **完全同构**；此时「AI 介入」在 **标注替代人**。  
  - **B. 直接 DPO / IPO 等**：偏好对 **跳过显式 RM**，进 DPO loss；「AI 介入」在 **造 y_w,y_l**。
4. **没有魔法第三种 loss**：RLAIF 不是新目标函数，而是 **偏好数据的自动化来源**；**loss 仍是 RM 分类 / PPO / DPO** 之一。

**Reward 从哪来**：若走 PPO，`reward = r_φ` 或 `R_verifier` 组合；若走 DPO，**不显式标量 reward**，偏好已编码在 **成对 log-ratio loss** 里。

**风险（要能答）**：裁判 **系统性偏见**（例如偏爱长文、某种格式）会被放大；与人标混合、**held-out 人评**、**拒绝采样低置信对** 是常见工程补丁。

### 面试怎么答

「RLAIF = 用强模型批量产偏好对或打分；后面要么训 RM+PPO，要么直接 DPO；要说明 AI 在标注侧，loss 侧没有单独叫 RLAIF 的式子。」

## 6. LoRA：低秩为什么常常够用

大矩阵的有效微调更新，经验上 **秩不高**；显式 `ΔW = B A` 把搜索空间 **限制在低维流形**，**冻结主干** → **省显存（少存优化器状态）**、**少动语言能力**。rank 靠 dev 扫，不是玄学常数。

### 6.1 LoRA 参数怎么设（可直接落地）

常见超参有：`r`（rank）、`lora_alpha`、`lora_dropout`、`target_modules`、学习率。

- `**r`（rank）**：容量旋钮。  
  - 经验起点：`r=8/16`（7B~13B 常见），任务难或风格跨度大可试 `32`。  
  - 现象：`r` 太小欠拟合，太大接近全参微调（显存/过拟合风险上升）。
- `**lora_alpha`**：LoRA 分支缩放，常见实现等效缩放为 `alpha/r`。  
  - 经验：常从 `alpha=16/32` 起；若 `r` 提高，常同步提高 `alpha` 保持更新量级。
- `**lora_dropout`**：LoRA 分支 dropout。  
  - 数据多且干净可 `0~0.05`；数据少或噪声大可 `0.05~0.1`。
- `**target_modules`（打在哪些层）**：  
  - 起步优先 `q_proj,v_proj`（性价比高、稳定）；  
  - 需要更强能力再加 `k_proj,o_proj`，或再扩到 MLP（`up/down/gate`）。  
  - 原则：先小范围打点，看收益再扩，避免一次铺满导致调参困难。
- **学习率**：LoRA 常比全参可用更大学习率，实践常见 `1e-4 ~ 5e-4` 起扫；若同时训 lm_head/embedding，通常给更小 lr 或分组 lr。

一个稳健起配（仅作起点）：

```
r=16, lora_alpha=32, lora_dropout=0.05
target_modules=[q_proj, v_proj]
lr=2e-4, warmup_ratio=0.03, weight_decay=0.0~0.1（按任务扫）
```

排障速记：

- 训练 loss 下不去：先加 `r` 或扩 `target_modules`，再看数据质量。  
- 训练集很好、验证差：减 `r`/增 dropout/早停/加通用混合数据。  
- 输出风格跑偏或遗忘：降 lr、加 KL 到参考、缩小可训练模块范围。

### 6.2 LoRA、QLoRA、LoRA+、DoRA：各解决什么问题

四者都是 **PEFT**：冻结（或部分冻结）预训练权重，只训少量增量参数，降低 **显存与优化器状态** 压力。差别在 **「省下来的显存从哪来」** 以及 **「更新方式是否更贴近全参微调」**。


| 方法        | 核心做法                                                                 | 主要解决什么问题                                                                                          |
| --------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **LoRA**  | `ΔW = B A`，低秩适配，只训 A/B                                               | **全参微调太贵**；在较小 rank 下接近全参效果                                                                       |
| **QLoRA** | LoRA + **4bit 量化** 存基础权重，计算时常用 NF4 + 双重量化；LoRA 适配器仍 FP16/BF16        | **单卡装不下大模型权重**；在 **消费级 GPU** 上训 7B～70B                                                            |
| **LoRA+** | 对 LoRA 的 **A 与 B 使用不同学习率**（常 `η_B > η_A`，如 B 用更大 lr 或固定比例）           | 标准 LoRA **A、B 同 lr** 与 **非对称初始化**（A 随机、B 初值为 0）不匹配，收敛慢、略欠拟合；LoRA+ 报告 **更快收敛、略提精度**，**不增加推理开销**    |
| **DoRA**  | 把权重分解为 **幅度（magnitude）+ 方向（direction）**；**方向** 用 LoRA 更新，**幅度** 单独可训 | LoRA 与全参微调差距 partly 来自 **只改方向、幅度学不好**；DoRA 更好拟合全参的 **幅值-方向** 更新模式，**精度常优于 LoRA**，推理时可合并 **无额外延迟** |


**QLoRA 与 LoRA 关系**：QLoRA **不是**另一种低秩结构，而是 **「量化底座 + LoRA 适配器」** 的训练配方。底座用 4bit 省显存；**梯度仍主要更新 LoRA 参数**（及可选的 norm 等）。面试别答成「QLoRA 秩更低」。

**LoRA+ 直觉**：B 矩阵负责把低秩特征 **映射回原空间**，对最终更新幅度影响大；给 B **更大学习率** 相当于承认「A 压缩、B 放大」两步 **灵敏度不同**。

**DoRA 直觉**：全参更新往往 **方向变一点、模长也变一点**；纯 LoRA 主要在 **方向子空间** 里动，DoRA 显式补 **模长通道**，缓解 **LoRA 追不上全参** 的那一段 gap。

**选型口述**：单卡要训大模型 → **QLoRA**；同卡要更快/更稳收敛 → 试 **LoRA+**；同 rank 要更高精度、愿多一点可训参数 → **DoRA**；资源够、任务极难 → 再考虑全参或更大 rank。

## 7. 灾难性遗忘

**现象**：强训某域后 **通用能力掉**。  
**原因**：小数据大步更新把表示 **拉进窄流形**。  
**缓解**：混合通用数据、小 lr、早停、KL 到参考、replay、LoRA 限自由度；评测 **别只看新域**。

### 面试怎么答

「遗忘是表示漂移；LoRA 不是免死金牌，只是少改底座。」

## 8. SFT 与 RL：checkpoint 怎么留、何时从 SFT 进 RL、怎么判断 SFT 已够

### 8.1 「先借点」在说什么——要存哪些 checkpoint

对齐管线里 **至少留三类存档**（名字因团队而异）：


| 存档                      | 典型用途                     | 常见选取方式                                                             |
| ----------------------- | ------------------------ | ------------------------------------------------------------------ |
| `**π_SFT`（或 best SFT）** | RL/DPO 的 **初始化**；人工评测对照  | dev **loss 最低** 或 **人工抽检最好** 的 step（别只存最后一个 epoch）                 |
| `**π_ref`（参考策略，常冻结）**   | PPO/GRPO/DPO 里的 **KL 锚** | **SFT 结束前 1～2 个稳定 checkpoint** 或 **与 `π_SFT` 相同**；要 **整个 RL 阶段不变** |
| **RL 中间档**              | 回滚 reward hacking、A/B    | 按 **验证奖励 + KL** 存 best；保留 **每隔 N step** 防崩                         |


**原则**：RL 不是「从基座直接上」——`**π_θ` 初值 = SFT**；`**π_ref` = 防止 RL 把语言训歪的锚**。DPO 同理：`**π_ref` 几乎总是冻结的 SFT**（见 §3）。

### 8.2 什么时候判断「可以从 SFT 进入 RL」

**可以进 RL 的信号**（满足大部分即可，不是单指标）：

1. **SFT 训练曲线**：train/dev CE **已进入平台期**（继续训 mainly 过拟合示范），而非仍在 **陡峭下降**（说明还没吃透 SFT，RL 会在差初值上乱探索）。
2. **格式与可读性**：对目标域 prompt **抽样生成**，能稳定输出 **约定格式**（分步推理、JSON、工具调用 schema）——**乱码、无限重复、严重偏题** 时应 **继续 SFT 或清数据**，不是加 RL。
3. **任务上有 非零、非饱和 的可优化空间**：
  - **可验证任务**（代码测例、数学题）：SFT 上 **pass@1 不是 0**（否则 RL 几乎收不到正奖励），也 **不是已顶满**（否则 RL 无增益）。  
  - **偏好任务**：人评或强模型评 **已有区分度**（好答案比差答案分高），否则 RM/RL 学不动。
4. **数据与奖励就绪**：RL 阶段的 **奖励定义、评测脚本、参考模型** 已固定；否则先 **RLAIF 造偏好** 或 **规则奖励**（见 §9、`06` 冷启动）。

**不宜进 RL 的情况**：

- SFT **严重过拟合**（train 很好、dev 很差）→ 先 **加通用数据 / 降 lr / 早停** 再谈 RL。  
- **奖励还没想清楚**（主观又没人标）→ 先 **DPO/人标** 或 **可验证规则**，别裸 PPO。  
- **算力不够 rollout** → 优先 **DPO（离线）** 或 **小 batch GRPO**，别硬上全量 PPO。

### 8.3 如何判断「SFT 已经训充分、可以交给 RL」

「充分」**不是** dev loss → 0，而是 **RL 要的先决条件满足**：

**（1）离线自动**  

- **held-out** 上 **loss 平稳** + **生成指标**（ROUGE/BLEU 仅作参考）+ **任务指标**（pass@k、F1、工具调用成功率）。  
- **格式校验率**：如 JSON parse 成功率、必需字段齐全率 **> 团队阈值**（如 95%）。

**（2）人工 / 强模型抽检（小但准）**  

- 固定 **50～200 条** 金标 prompt，看 **可读性、指令遵循、安全性**；**严重幻觉/拒答异常** 要先修 SFT。  
- 对 **将要用于 RL 的同一批 prompt**，看 SFT 采样 **方差是否可控**（同一 prompt 多条不会一条满分一条乱码）。

**（3）给 RL 留空间的启发式**  

- **可验证任务**：SFT **pass@1 在 20%～70%** 一类区间常适合 RL（太低纯探索，太高没必要 RL）——**区间随任务调**，面试说 **「非零非饱和」** 即可。  
- **KL 预检**：用 **即将冻结的 `π_ref`** 测 SFT 模型，若 **平均 KL 已极大**，说明 SFT 已离参考很远，要检查 **是否存错 ref** 或 **SFT 步数过多**。

**口语总结**：「SFT 充分 = 格式稳、任务有信号、dev 平台期；不是 loss 越小越好才进 RL。」

### 面试怎么答

「先存 best SFT 和冻结 π_ref；进 RL 前看曲线平台期、抽样格式、可验证 pass 非零非饱和；SFT 还在乱码就别上 RL。」

## 9. 奖励形态：连续 / 二值 / 阶梯；用大模型打分与要不要微调

### 9.1 三种奖励形态各是什么、有什么影响


| 形态           | 例子                               | 对训练的影响                                                                               |
| ------------ | -------------------------------- | ------------------------------------------------------------------------------------ |
| **二值 0/1**   | 单元测试过/不过、答案对错                    | **信号稀疏**、方差大；但 **无歧义**，和 **GRPO 组内比较**、**RLAIF 成对** 很合拍；适合 **代码/数学/工具成功**            |
| **连续 [0,1]** | RM 标量、模型打 0.87 分                 | **梯度更细**、可区分「略好/略差」；但 **标定难**，RM 偏了会 **系统性 reward hacking**；PPO/GRPO 常做 **归一化/clip** |
| **阶梯 / 分档**  | 0 错 / 0.3 部分对 / 1 全对；或 rubric 三档 | 在 **稀疏与细腻之间折中**；减少「全对全错」导致的 **零梯度组**（DAPO dynamic sampling 过滤无效组）；要 **防模型刷中间档**      |


**选型原则**：能用规则自动判分的任务（代码、数学、工具成功）优先用 **二值或阶梯**，既便宜又可复现；主观质量（有用性、礼貌、风格）适合 **连续 RM** 或直接走 **成对偏好 DPO**；长链推理常采用 **结果二值 + 过程格式分**（格式错直接 0）。

**与优势估计的关系**：连续奖励进入 GRPO 时仍可用组内减均值做优势；若同一组内所有奖励完全相同，中心化后 **A_i ≈ 0**，该 prompt 几乎无梯度，训练时通常丢弃该组或更换 prompt。

**面试口述**：二值适合可验证任务，连续适合主观打分但要防 RM 偏，阶梯是折中；选型看任务能否规则判定。

### 9.2 用大模型做奖励打分：在干什么、工程怎么做

**在干什么**：用 **强 LLM（Judge）** 读 `(prompt, response)` 或 `(response_a, response_b)`，输出 **分数、排序或 rubric 各维分数**，作为 **RL 的 reward** 或 **造 DPO 偏好对**（即 **RLAIF**，§5）。

**典型流水线**：

```text
rollout：当前策略 π_θ 对 x 生成 y
  → 组装 judge prompt（含 rubric、可选参考答案、安全规则）
  → 调 Judge API / 本地 vLLM（温度常设 0 或很低）
  → 解析输出（JSON 分数 / A>B / 1-5 分）
  → 写入 reward 表 / 直接进 PPO·GRPO buffer
  →（可选）与人标或规则分融合：R = w_rule·R_rule + w_llm·R_llm
```

**工程要点**：

1. **与训练解耦**：Judge **异步批处理**（队列 + worker），别在 **训练 critical path** 上同步调 API。
2. **缓存**：`(hash(x,y), judge_version) → score`，同一回复 **不重复烧钱**。
3. **解析鲁棒**：强制 Judge **JSON 输出**（`15` §5.1）；失败 **重试 / 默认低分 / 丢弃样本**。
4. **版本锁**：Judge **模型名、prompt 模板、温度** 进 metadata；换 Judge = **新实验**，不可与旧曲线横比。
5. **成本与吞吐**：大 rollout 时 Judge 往往是 **瓶颈** → 采样 **子集打 LLM 分**、其余用 **小 RM** 或 **规则**；或 **离线造偏好 → DPO** 减少在线 Judge 次数。
6. **防串通**：Judge 别用 **正在训的同一 checkpoint**；用 **更强、冻结** 的模型。

**在线 vs 离线打分**：纯同步在线（rollout 完立刻等 Judge 返回再更新）几乎没人用，会把训练卡死。主流做法是**异步**：策略 rollout 产生样本后直接丢队列继续训练，Judge worker 后台打分写回；下次采样优先用已打好分的样本，或规则分与 LLM 分混合使用。

**异步带来的 off-policy gap**：rollout 时用的策略是 π_old，等 Judge 打分回来时策略可能已经更新到 π_current，样本就成了 off-policy。如果直接用旧策略生成的轨迹算梯度，会引入偏差。常见处理方式：
- **重要性采样校正**：在策略梯度项里乘 importance ratio `π_current(y_i) / π_old(y_i)`（或其截断版），把旧策略样本的贡献重新加权到当前策略下。
- **样本时效限制**：队列设置最大长度或最大更新步数，超过就丢弃（staleness threshold），保证样本最多只落后 K 次更新。
- **Value model 辅助**：当有 critic V 时，可以用 V-trace、Retrace 或类似 off-policy correction 算法；即使 GRPO 系不训 V，V 仍可作为 baseline 降低方差。
- 实际工程里很多人选择**容忍轻度 off-policy**：只要策略更新步长不大、队列不长，group baseline 本身就有一定鲁棒性，就不做完整 importance sampling，直接用 delayed reward 训练。

**分数归一化（跨组/跨 batch 漂移）**：LLM Judge 不同 batch 打分量级可能差很大（一组 1-2 分，下一组 10-100 分），直接喂原始分会导致 advantage 尺度不稳、梯度爆炸或消失。常见处理方式：

- **Group 内 z-score**（GRPO/GSPO 默认）：同一 prompt 的 G 条样本内部做 `(R_i - μ_G) / (σ_G + ε)`，把本组内相对好坏拉到同一尺度。
- **Running whitening**：维护最近若干 batch 或全局的 reward 均值和方差，对新 reward 做标准化后再进 advantage 计算。
- **Per-batch normalization + clip**：每个 batch 内部归一后，再把 advantage clip 到合理范围（如 [-5, 5]）。
- 无论哪种，都建议在 advantage 进入策略梯度前再做一次 **全局或滑动窗口归一化**，防止量级漂移直接影响梯度大小。

**Value model（critic）的作用**：当使用传统 PPO（有 V）时，LLM Judge 只提供 **原始奖励 r**，Value model V(s) 的作用是估计「在当前状态下的预期回报」，用来计算 advantage（GAE）。即使 r 的绝对值在不同 batch 漂移，V 学到的是相对 baseline，能部分吸收漂移，降低策略梯度方差。GRPO/GSPO 路线通常**弱化或不使用 V**，直接用 group 内统计做 baseline，因此 group 内归一化就显得尤为重要。

### 9.3 大模型做奖励打分，要不要微调？

**分两种角色，别混**：


| 角色              | 要不要微调              | 说明                                                                                            |
| --------------- | ------------------ | --------------------------------------------------------------------------------------------- |
| **Judge（打分器）**  | **常要**（若长期、大规模、域内） | 通用 GPT-4 类 **贵、慢、口径漂移**；用 **人标偏好对** 训 **小 RM（7B 级）** 可 **稳定、便宜**；OpenAI 传统 RLHF 也是 **单独训 RM** |
| **Judge（仅造数据）** | **可不微调**           | 用强模型 **批量产 (y_w, y_l)** → **DPO**；Judge 不进训练环                                                 |
| **被训的策略 π_θ**   | **不是「为打分而微调」**     | 策略只接收 **标量 reward**；别用 **同一模型给自己打分** 且无约束                                                     |


**何时必须微调 RM / Judge**：

- 领域 **术语重**（医疗、法律、内部工单），通用 Judge **系统性误判**。  
- 需要 **毫秒级、海量** 打分，API 扛不住。  
- 产品 rubric **细**（多维度、阶梯），要用 **人标数据对齐 Judge**。

**何时不必微调**：

- 探索期 **少量实验**、**规则+强模型 API** 够用。  
- 任务 **可完全规则化**（单测、SQL 结果集对比）。

**面试一句**：「在线 RL 要稳定奖励，长期用 **专人标训的小 RM** 或 **冻结强 Judge+缓存**；RLAIF 造偏好可以 **不微调 Judge，只微调策略 via DPO**。」

### 面试怎么答

「LLM Judge 主流异步打分，训练不等返回；异步会让样本变成 off-policy，可用 importance ratio 校正或限制样本时效（staleness threshold）；分数漂移用 group z-score 或 running whitening；有 V 时它可做 baseline 或 off-policy correction，GRPO 系主要靠 group 内统计。」

## 10. 场景里该用 8B、30B 还是更大？（选型思路）

这不是 **「越大越好」**，而是 **任务难度 × 延迟/成本 × 数据 × 评测** 四维折中。

### 10.1 先问清场景类型


| 维度        | 偏小模型（7B～8B）往往够 | 倾向 30B+ 或 MoE（如 30B-A3B 激活） |
| --------- | -------------- | --------------------------- |
| **推理深度**  | 抽取、分类、短回复、单步工具 | 多步数学/代码、长链 CoT、复杂规划         |
| **知识**    | 窄域、RAG 外挂知识为主  | 强内置知识、少检索、跨域综合              |
| **格式**    | 简单 JSON、模板化    | 长文、多工具、弱约束生成                |
| **延迟/成本** | 在线高 QPS、边缘部署   | 可接受慢、批处理、离线                 |
| **数据**    | 高质量小数据 + LoRA  | 大数据全参或长训                    |


### 10.2 推荐决策流程（可复述）

1. **用 8B（或当前最小可用）做 SFT + 同一评测集**，记 **任务主指标**（pass@1、人工分、工具成功率）。
2. **看失败模式**：
  - **格式/指令 follow 失败** → 先 **数据与 SFT**，未必加大模型。  
  - **明显能力不足（推理错、知识缺）** → 上 **30B 或 MoE**，或 **RAG+8B**。  
  - **8B 接近饱和但差一点** → **蒸馏 30B→8B**、或 **RL on 8B**、或 **略增容量**。
3. **算经济账**：30B 推理 **显存与延迟** 常为 8B 的 **数倍**；MoE 可能 **总参大但激活参接近 8B**（见 `06`）。
4. **量化**：8B INT4 常是 **成本敏感首选**；30B 要 **多卡或强量化** 才上生产。
5. **别跳过评测**：**同一 prompt 集** 上 A/B **8B vs 30B**，看 **是否 worth it**；有时 **8B+RAG+工具** > **裸 30B**。

### 10.3 和本笔记其它章的衔接

- **RL 阶段**：奖励若 **很稀疏**，小模型 **更难探索** → 常 **大模型 SFT 冷启动 + 蒸馏** 或 **直接大模型 RL**（`06` R1）。  
- **Agent**：多轮 tool **上下文长** → 除模型大小外还要看 **上下文长度与成本**（`15` §4）。

### 面试怎么答

「先小模型+同一评测；格式问题修数据，推理/知识不够再加大或 RAG；用失败模式和成本决定，不是无脑 30B。」

## 本篇小结

- SFT = **TF 下的逐步 CE**；与推理 **分布错位** → exposure bias。  
- RLHF = **RM（成对偏好）+ PPO（KL 约束）**；DPO = **(y_w,y_l)+π_ref 的成对 sigmoid loss**，**离线**、无 value。  
- GRPO = **组内相对回报当优势**，接 `**12` §5** 展开。  
- **GSPO** = 组采样保留 + **序列级 importance** 降长链方差；**DAPO/VAPO** = 在 GRPO/PPO 上的 **采样/clip/value** 增强。  
- **LoRA / QLoRA / LoRA+ / DoRA** = 省参数量级不同（量化 vs 学习率分解 vs 幅值-方向）。  
- RLAIF = **偏好数据来源**；**loss 仍是 RM/PPO/DPO 家族**。  
- **§8**：**π_SFT / π_ref** 存档；SFT **平台期+格式稳+任务信号非零非饱和** 再 RL。  
- **§9**：奖励 **二值/连续/阶梯**；LLM Judge **异步+缓存**；长期 **训 RM** vs 短期 **API 造 DPO**。  
- **§10**：**8B→30B** 用 **同一评测 + 失败模式 + 成本**，非越大越好。
