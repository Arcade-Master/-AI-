# 00｜写作与答疑规约（长期维护）

适用范围：`面试笔记/` 全部文档、配套问答、后续增补与改写。  
目标：内容**准确、可复述、少废话、少坑点**，避免“写了像没写”。

---

## 1. 总原则（必须遵守）

1. **先正确，再好看**：概念、公式、边界条件优先于修辞。  
2. **面试可口述**：每节都能在 30~90 秒内讲清主线。  
3. **不模板化凑格式**：避免只给“一句定义”就结束；该讲透就讲透。  
4. **最小但完整**：不灌水，但高频追问点必须前置写清。  
5. **统一符号与口径**：同一概念在不同文档中说法一致。

---

## 2. 文档写作规约（生成/改写时）

### 2.1 每个关键知识点的最低完备度

对高频考点（优化器、注意力、并行、损失函数、对齐训练等），至少包含：

- **是什么**（定义/角色）  
- **怎么算**（最小公式或伪代码）  
- **为什么**（直觉 + 原因）  
- **容易错在哪**（常见误解/坑）  
- **工程上怎么做**（实践口径、默认做法）

如果缺任一项，视为“未写完整”。

### 2.2 公式与符号要求

- 公式出现时，**符号必须就地解释**（如 `g_t, β, wd, S, d_k`）。  
- 向量/张量与标量要写清（避免把 `Δθ` 讲成标量）。  
- 给公式时优先给**常用工程版本**（如 AdamW 的 decoupled 写法）。  
- 复杂点至少给一个**小数值例子**（2 维示例优先）。

### 2.3 工程细节要求

- 说明“理论定义”与“框架实现”的差异（例如 Adam vs AdamW、动态 loss scaling）。  
- 说明默认超参是**经验值**，不是数学常量。  
- 明确哪些内容会因版本变化（Megatron、DeepSpeed、PyTorch）。

### 2.4 结构要求

- 标题直接表意，避免空泛标题。  
- 段落顺序：**概念 → 公式 → 直觉 → 坑点 → 面试口述**。  
- 代码块只放必要内容，避免把解释文本误塞进代码块。  
- 长节中可加“对照表”，但表格必须有决策价值（不是装饰）。

---

## 3. 问答解答规约（对话回答时）

1. **先回答用户问题本体**，再扩展。  
2. 用户明确“看不懂”时，必须切换到：  
   - 具体数值例子  
   - 逐步推导  
   - 对比法（A vs B）  
   不能继续抽象口号。  
3. 禁止回避式表达（如“这个看实现”“大概如此”）后不落地。  
4. 解释完后给一句“如何在面试里说”，但不能替代完整解释。  
5. 用户反复追问同一点时，应主动补文档，不等再次提醒。

---

## 4. 必补清单（高频漏写点）

后续生成新文档时，默认检查以下是否已写：

### 4.1 损失函数/概率

- softmax 稳定写法为何必要（减 max）  
- sigmoid 梯度消失原因与导数形态  
- 二分类里 softmax 与 sigmoid 的等价关系  
- CE 与 MSE 的任务匹配原因（概率空间 vs 欧氏空间）

### 4.2 注意力/Transformer

- `Q,K,V,W_O` 各自角色  
- 多头输出到 `W_O` 再到残差/FFN 的路径  
- Prefill 与 Decode 的计算形态差异  
- KV Cache 为何只存 K/V、不存 Q

### 4.3 优化器/精度

- EMA、`β`、`g_t` 的定义  
- AdamW 中 L2 与 weight decay 的区别与关系  
- “扭曲”在 Adam 中如何发生（坐标级例子）  
- FP16/BF16 训练为何常保留 FP32 master weights + optimizer states  
- Loss scaling 的 `S` 是什么、静态/动态如何工作

### 4.4 分布式/显存

- 显存拆账：参数/梯度/优化器状态/激活/临时 buffer  
- 激活量级与 `B,S,H,L`、`S²` 项关系  
- 并行后单卡峰值为何仍会出现  
- Megatron 批大小与并行维约束（整除关系）

---

## 5. 质量红线（禁止）

- 只给术语不给解释。  
- 只给结论不给公式或例子。  
- 把“经验值”写成“必然定律”。  
- 段落看似完整但无法回答“为什么”。  
- 用户已明确不懂仍重复抽象表述。  
- 为了形式完整而堆模板句。

---

## 6. 维护流程（每次修改后）

1. 检查是否补到了“用户实际卡点”，而非只补格式。  
2. 检查新增内容是否与已有章节口径冲突。  
3. 若新增了关键节，更新 `00-目录.md` 索引。  
4. 保持增量克制：补必要知识，不做无关重写。

---

## 7. 默认写作风格

- 中文，直白，技术准确。  
- 优先“解释清楚”而不是“讲得漂亮”。  
- 允许短句和口语化，但术语和公式必须严谨。  
- 对不确定实现要标注版本依赖，不假装确定。
