# 12｜传统强化学习、REINFORCE++、PPO、GRPO、Value、采样与相对优势

对应：**`面试答题.md` 新增**（第 9～12 行）；与 **`05`** 中 RLHF/DPO/GRPO 概要互补，本篇把 **计算过程与概念** 写细。

---

## 1. 对齐层与 RL 题在面试里的关系

多模态 **对齐层**（见 `11` 篇）解决 **表示接口**；RL（本篇）解决 **在奖励信号下更新生成策略**。工业里常见管线：**SFT 对齐格式 → RM/规则奖励 → PPO/GRPO**。

---

## 2. 传统强化学习：策略梯度与 baseline

**目标**：最大化期望回报 `J(θ) = E_{τ~π_θ}[ R(τ) ]`。

**REINFORCE（蒙特卡洛策略梯度）**：

```
∇_θ J ≈ E[ ∇_θ log π_θ(a|s) · G ]
```

`G` 是从该步到回合结束的 **回报和**（或折扣回报）。

**问题**：方差 **极大**——同一策略下 `G` 波动大，梯度噪声大、收敛慢。

**经典减方差技巧**：

- **Baseline `b(s)`**：用 `G - b(s)` 代替 `G`，**期望梯度不变**、方差常下降。常用 **可学习的 Value 网络 V(s)** 估计 `E[G|s]`。  
- **因果性（per-token）**：生成 token 时只对 **尚未生成的未来** 回报回传，避免「用未来归因过去」的方差浪费（实现上用 **回报 mask** 或 **逐 token advantage**）。

---

## 3. 「REINFORCE++」你可能忘了：面试怎么圆？

**「++」不是单一全世界统一标准**，不同团队指代不同。面试可以 **诚实分层答**：

1. **若指「带 baseline / advantage 的 REINFORCE」**：说明你在 **方差缩减** 上做了 baseline、或 **归一化优势**（减均值除标准差）。  
2. **若指「多采样 + 相对排序」」类 GRPO 思想**：同一 prompt **多条 rollout**，用 **组内相对分数** 当优势，**少依赖 critic**。  
3. **若指某篇具体论文/开源实现**：答「名称我需对照论文，但核心一般是 **降低策略梯度方差 + 稳定 KL/熵正则**」。

面试官要听的通常是：**你知道 REINFORCE 高方差**，且知道 **baseline / GAE / 归一化 / 多条采样** 都是为了 **可训**。

---

## 4. Value 是什么？为什么在 PPO 里重要？

**Value 函数 `V(s)`（或 `V(s_t)` 在序列里）**：在策略 `π` 下，从状态 `s` 出发 **期望总回报**（可含折扣）。

**作用**：

- 作为 **baseline**：`A = G - V(s)`，减小梯度方差。  
- **Actor-Critic**：critic 学 `V`，actor 用 `A` 更新 `π`。

**注意**：在 **GRPO** 一类方法里，可用 **组内相对 reward** 代替学出来的 `V`，从而 **弱化或去掉独立 value 网络**，这是与经典 PPO 的 **工程取舍**。

---

## 5. PPO：计算过程（按一次迭代口述）

**输入**：当前策略 `π_θ`、旧策略 `π_old`（或上一步参数）、一批轨迹或（prompt, response）对。

1. **Rollout**：用 `π_old` 采样得到 response，环境/RM 给出 **reward `R`**（可 token 级或序列级）。  
2. **优势估计 `A`**：  
   - 有序列价值时：**GAE-λ**：用 `δ_t = r_t + γV(s_{t+1}) - V(s_t)` 递推组合，平衡偏差–方差。  
   - 只有终端奖励时：可把 **整条 reward** 回灌到最后非 pad token，或用 **reward 模型逐段打分** 近似。  
3. **比率**：`r_t(θ) = π_θ(a|s) / π_old(a|s)`（实现里用 log 差 exp）。  
4. **Clip 目标**（单样本形式直觉）：

```
L_clip = min( r(θ)·A, clip(r(θ), 1-ε, 1+ε)·A )
```

防止一步更新把策略 **拉太远** 导致不稳定。  
5. **加熵 bonus**（可选）：鼓励探索。  
6. **KL 惩罚或约束**：贴近参考模型（SFT）。  
7. **多 epoch 小步更新**同一批数据（注意 **不要过拟合** 同一 batch）。

**Value 在 PPO 里**：critic 用 **MSE** 等拟合 **回报目标**（如 `n-step return` 或 `GAE + V` 的 target）。

---

## 6. GRPO：计算过程（与 PPO 对照）

**核心**：同一 prompt 下 **采样一组输出** `{y_1,…,y_G}`，用 **组内统计** 构造优势，**弱化 critic**。

典型步骤：

1. **组采样**：对同一 `x`，从当前策略采 `G` 条 `y_i`。  
2. **打分**：规则执行 / 单元测试 / RM → 得标量 `r_i`（可二值也可连续）。  
3. **组内标准化**（相对优势直觉）：

```
A_i = (r_i - mean({r})) / (std({r}) + eps)
```

或只用 **排名** 转成分数（实现各异）。  
4. **策略梯度**：用 `A_i · ∇ log π(y_i|x)` 一类目标更新；常配合 **KL 到参考策略** 防止崩。  
5. **无显式 value** 或 value 仅作可选辅助。

**为何适合推理模型**：数学/代码 **可验证奖励** 清晰，**多条采样** 提供自然 **相对比较**，减少 **价值估计误差** 带来的噪声。

---

## 7. GRPO 采样怎么做？「相对优势」你怎么理解？

**采样**：温度、top-p、或 **束搜索 + 多样化**；关键是 **同一条件下多条独立轨迹**，覆盖 **对错两类** 才有梯度信号。

**相对优势理解**（面试金句）：

- 绝对 reward 常有 **尺度漂移、模型间不可比**；  
- **组内减均值**：突出「这条比同批平均好还是差」；  
- **除标准差**：把不同 prompt 间 **方差差异** 压一压，训练更稳。  
- 与 **self-play / Bradley-Terry** 思想相通：**比较** 比 **绝对分** 更鲁棒。

---

## 8. 与 `05` 篇的衔接

- **RLHF**：RM + PPO 是工业经典。  
- **DPO**：绕过显式 RL。  
- **GRPO**：**组相对 + 弱 critic** 适配 **可验证推理奖励**。

---

## 小结

- **REINFORCE**：对；**方差大**；**baseline/value** 是正经解。  
- **PPO**：**ratio + clip + advantage +（可选 value）**。  
- **GRPO**：**组采样 + 组内相对优势 + KL**，**少依赖 value**。  
- 「REINFORCE++」：**按方差缩减与多采样相对优势** 答，比硬背名字安全。
