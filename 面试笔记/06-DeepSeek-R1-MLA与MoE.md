## 1. DeepSeek-R1 是什么：不止「会推理的模型」

**R1 系列**（公开讨论语境下）：强调 **长链推理（chain-of-thought 风格）**、数学/代码等 **可验证任务** 上的表现；训练管线常结合 **高质量冷启动 SFT + 大规模强化学习（含 GRPO 类方法）** 与 **蒸馏/数据飞轮**（以官方技术报告为准，面试答「公开披露路线」即可）。

**核心特点（答法）**

- **显式推理过程**：鼓励模型输出可检查的中间推理，再收敛到答案（产品形态上可能对用户隐藏或摘要，但训练侧强调该能力）。
- **强化学习占比高**：相对「只做 SFT 的 instruction 模型」，更依赖 **环境反馈/规则奖励** 塑造探索与纠错。
- **系统与架构配套**：如 MLA 降低推理 KV、MoE 提高参数容量与训练成本权衡等（视具体模型版本）。

**为何推理强（因果链，不是形容词堆砌）**

1. **数据与目标对齐**：针对推理轨迹与最终结果双重优化。
2. **RL 探索**：在巨大解空间中通过试错学会 **回溯、验证、分解**。
3. **基座容量与上下文**：足够参数与上下文支撑长推导。

**与传统 instruction 模型区别**

- Instruction 模型：偏 **模仿人类写法** 的 SFT + 少量对齐；强在遵循指令、风格、通用对话。
- R1 路线：偏 **过程正确性与任务得分**；更强调 **可验证奖励** 与 **长程一致性**（仍会有幻觉，只是缓解方向不同）。

## 2. MLA（Multi-head Latent Attention）如何节约 KV Cache？

**KV 瓶颈**：自回归 decode 每层每步都要读历史 K、V；层数 × 序列长度 × head 维 × batch 使 **显存与带宽** 快速增长。

**MHA（标准多头）**：每头独立 K、V，KV 与 **头数** 成正比。

**MQA**：所有头 **共享同一套 K/V**，KV 随 head 数不线性放大，推理省缓存，但表达力可能受限。

**GQA**：分组共享（几头共享一组 KV），在 **省缓存与质量** 间折中。

**MLA（思想级回答）**：不把完整 K、V 直接存成高维张量，而是对 KV 做 **低秩/潜空间压缩**（latent），缓存 **更小维度的压缩表示**，在 attention 计算时再 **解压/投影** 回可用空间。这样 **单次读写带宽与缓存占用** 下降。

**为何不太伤性能**：语言建模里跨 token 的依赖 **近似低秩** 是经验观察；压缩发生在 **对预测冗余度较高** 的 KV 子空间，配合足够容量与训练，可把损伤压到评测可接受范围（仍依赖实验与规模）。

## 3. R1 路线里「冷启动」SFT 的目的

**不能直接 RL 的典型原因**

- RL 从 **随机或弱策略** 起步，探索空间巨大，**稀疏奖励** 下很难学出可读、可用的推理格式。
- 没有基本格式与语言稳定性，RL 容易 **模式坍塌**、乱码、或钻奖励漏洞。

**冷启动数据作用**

- 给模型 **示范推理形态**（分步、符号、自我检查等），提供 **可学习的先验策略**。
- 稳定 **输出分布与 tokenizer 习惯**，让后续 RL 在「合理流形附近」微调。

**对稳定性与可读性**

- 稳定性：减少 RL 早期 **高方差更新**。
- 可读性：先模仿人类/高质量合成 **可读 CoT**，再 RL 优化正确性，避免「只对答案对、过程一团糟」。

## 4. MoE（Mixture of Experts）

**原理**：每层含多个 FFN expert，**门控网络**按 token 动态选 **top-k** 个 expert 计算；**激活参数**远小于总参，故 **单位算力下容量大**。

**为何可能降低训练成本（相对 dense）**：同样 FLOPs 预算下总参数量可更大（仅部分 expert 激活）；但 **工程复杂度与通信** 上升。

**Expert routing**：门控 logits → softmax/top-k → dispatch 到 expert；需处理 **token 负载不均**。

**Load balance 重要性**：若少数 expert 吃满、多数 idle，**GPU 利用率差**且门塌缩；常用 **auxiliary load-balancing loss**、容量因子等。

**通信压力**：跨设备 scatter/gather token 到 expert 所在设备（依赖实现），**all-to-all** 可能成为瓶颈。

### 4.1 MoE 相比 Dense 有什么好处？

- **容量 vs 算力**：总参数量可 **远大于** 同 FLOPs 的 dense 模型 → **更强记忆与模式库**，每 token 只激活子集。  
- **训练吞吐**：在固定算力下，单次 step 可 **「更大名义参数量」**（视实现）。  
- **推理**：若部署 **专家子集** 或 **蒸馏** 到 dense，可换 **延迟**；纯 MoE 服务要扛 **路由与 all-to-all**。

**代价**：**负载均衡、通信、调试难度、checkpoint 体积**；小数据任务可能 **过拟合某些 expert**。

### 4.2 MoE 的「演变过程」（面试时间轴口述）

1. **早期 MoE / Switch Transformer**：证明 **极大稀疏模型** 可训；强调 **top-1 / top-k** 与 **负载均衡 loss**。  
2. **GShard / GLaM**：**跨设备专家并行**、大规模 TPU 实践。  
3. **开源与 LLM 时代**：Mixtral 等 **开源 MoE** 降低门槛；闭源大模型广泛采用 **稀疏 FFN + 共享 attention**。  
4. **工程化**：与 **TP/EP（Expert Parallel）**、**蒸馏、合并专家** 结合，服务侧 **降延迟**。

（细节以各论文/官方报告为准，答 **「稀疏激活换容量 + 并行分片成熟」** 即可。）

### 4.3 MoE 训练技巧（高频考点）

- **辅助负载均衡损失**：惩罚 **专家使用频率偏离均匀**；系数过大损伤 **语言建模**，需扫。  
- **容量因子（capacity factor）**：每 expert 每步最多处理 token 数上限；防 **热点打爆**，溢出 token **drop 或二次路由**（依实现）。  
- **z-loss / 稳定 logits**：减轻门控 **极端 logits** 导致的不稳定。  
- **精度**：router 与 expert 计算可用 **BF16**；注意 **all-to-all 与随机舍入**。  
- **评估**：除 **ppl** 外看 **per-expert utilization 直方图**。

## 小结

- R1 类模型：**推理形态 + RL + 系统结构** 三位一体叙述。
- MLA：**压缩 KV 表示** 换缓存与带宽；与 MHA/MQA/GQA 放同一坐标系对比。
- 冷启动：**给 RL 可学的初值与格式**。
- MoE：**条件计算换容量**，代价是路由与通信；**演变 = 稀疏训练 + 分片并行 + 开源与工程化**；**训练技巧围绕负载均衡与稳定性**。
