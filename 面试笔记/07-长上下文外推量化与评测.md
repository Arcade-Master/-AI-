# 07｜长上下文外推、量化与评测

**RoPE 公式与相对位置推导** 在 `**02` §7**（属于 Transformer 结构，不在本篇重复）。  
本篇：**推理长度超过训练窗时会发生什么、怎么救** → **训后量化** → **怎么评模型**。

---

## 1. 长上下文外推：外推是什么

**训练上下文长度**记为 **L_train**（例如预训练/SFT 时常见 4k、8k、32k，以实际 checkpoint 为准）。**推理时**若整段输入+已生成长度 **L_infer > L_train**，就叫 **长度外推（length extrapolation）**：模型要在 **训练时没怎么见过的绝对位置、以及更大的相对距离 n−m** 上继续算 attention。

这和「把 8k 窗口里的 RAG 片段塞满」是一类问题：不是换算法，而是 **同一个 RoPE/位置机制在更长的 m、n 上跑**。RoPE 下分数形如 `**q^T R_{n-m} k`**（见 `**02` §7.3**），外推时恶化的往往是 **(n−m) 很大** 或 **绝对 m、n 很大** 时，旋转角 **m·θ_i、n·θ_i** 落在训练分布之外。

---

## 2. 外推为什么会变坏

分三层说，避免只背「分布外」四个字。

**（1）相位 / 相对距离 OOD**  
训练只覆盖 **|n−m| ≤ L_train−1** 量级、以及 **m·θ_i** 在有限范围内的组合。拉到 **2×、4×** 长度时，许多维度对上的 **cos(m·θ_i)、sin(m·θ_i)** 会进入 **训练极少见到的相位**，`q^T R_{n-m} k` 的数值分布漂移，softmax 权重形状变怪——表现为 **远端 token 接不住、重复、胡言**。

**（2）注意力形态变化**  
即使勉强能算，**极长序列** 上 softmax 在更多 key 上归一化，**熵变高或变尖**（取决于分数尺度）；再叠加 **NTK / 插值** 等改法若和训练不一致，需要 **少量继续微调** 才稳。这是 **行为层** 问题，不全是「矩阵乘错了」。

**（3）工程叠加**  
**KV Cache** 变长 → 显存与 **BF16/FP16 累积误差**；极长 prefill 的 **激活峰值**（见 `**04`、`08`**）。这些不推翻 RoPE 公式，但会让 **长文 benchmark** 比短窗更难复现。

### 面试口述

「外推 = 推理长度超过训练窗；RoPE 下大相对距离和大绝对位置的相位 OOD，再加长序列注意力与 KV 工程因素。」

## 3. 常见缓解手段（记机制，不背口号）

**位置插值（Position Interpolation, PI）**  
把推理时的位置下标 **m 按比例缩小** 映射回 **[0, L_train]**，例如用 **m' = m · (L_train / L_infer)** 再代入 RoPE。效果：**相位回到训练见过的范围**；代价是 **细粒度绝对位置变糊**，远距依赖可能变软，常配合 **短继续训练**。

**NTK-aware scaling**  
不只做线性压缩索引，而是 **按维度调整有效 θ_i**（让高频维别过快转出分布、低频维保留长距），属于 **启发式修正**；不同实现细节不一，面试说清 **「调频率/带宽，缓和相位 OOD」** 即可。

**YaRN**  
在插值基础上 **再调注意力温度 / 部分维的缩放** 等组合，面向 **极长上下文** 榜；细节以论文与开源 config 为准，口径记 **「插值 + 注意力锐度/分段频率」**。

**实操共识**：改 RoPE 尺度后 **最好有长文微调或 SFT 一段**；零样本硬拉 128k 常不如 **训练窗内 RAG 切块**（见 `**13`**）。

## 4. 量化：要解决什么、INT8/INT4 动谁

大模型 **FP16/BF16 权重** 占显存大头（7B 量级就十几 GB）。**量化** 用更少 bit 存同一权重的近似值，换 **更低显存、可能更高吞吐**，代价是 **数值误差 → logits 漂移 → PPL 升或任务掉点**。

**权重量化**：`W` 存 INT8/INT4，算前 **反量化** 到 FP16，或走整型 GEMM。  
**激活量化**：中间层 `A` 也压 bit → 更难，因 **动态范围随 batch/输入变**。  
**W4A16（常见部署）**：权重 4bit，**激活仍 FP16/BF16**；LayerNorm、softmax 多仍 FP，实现相对稳。

**Outlier（离群通道）**：少数权重/激活维度 **极大**。若全张量共用一个 **scale**，outlier 会把大部分值 **挤进极少数量化 bin**，有效精度崩——后训量化方法多在争 **保护谁、把难量的尺度挪到哪**。

## 5. GPTQ / AWQ / SmoothQuant（训后三条线）

前提：**基座已训好**，用 **校准集** 估 scale，一般不做全量重训。

**GPTQ**  
按层、按列（或块）**贪心**量化权重，用 **近似 Hessian** 决定顺序与步长，使 **量化误差对层输出** 影响尽量小。主要产出 **INT4 权重 + FP16 激活** 的 W4A16。

**AWQ（Activation-aware）**  
在校准集上统计：**哪些权重列放大后会让激活变大**，这些列 **少压 bit 或单独 scale**，其余正常压。仍是 **以权重量化为主**，但 **选保护对象看激活**。

**SmoothQuant**  
对一层做 **等价变换**：把 **激活上的大尺度** 用 **权重吸收**（形如 `Y = (X/s)·(sW)`），让 **X 更好用 INT8**，权重略调，目标是 **W8A8**（权重+激活都 8bit），服务 TensorRT-LLM 一类栈。


| 方法          | 主要压谁  | 核心手段         | 常见形态  |
| ----------- | ----- | ------------ | ----- |
| GPTQ        | 权重    | Hessian 贪心逐列 | W4A16 |
| AWQ         | 权重    | 按激活敏感度保护列    | W4A16 |
| SmoothQuant | 权重+激活 | 平滑尺度到权重侧     | W8A8  |

## 6. 评测：PPL、公开榜、线上

**PPL（困惑度）**  
在测试文本上对每个 token 算 **负对数似然** 再指数：

```
NLL = mean_t( -log p(y_t | y_<t) )
PPL = exp(NLL)
```

**越低越好**（模型越不「惊讶」于真实续写）。**局限**：主要量 **语言建模**；Chat 的 **有用、安全、跟指令** 与 PPL 可脱节。手撕时分母只对 **有效 token**（见 `[手撕代码/AI手撕/03-手撕PPL.md](../手撕代码/AI手撕/03-手撕PPL.md)`）。

**公开 benchmark**（MMLU、GSM8K、HumanEval 等）  
固定题型离线榜；警惕 **数据污染、刷榜、与真实 query 分布不一致**。作 **相对趋势**，重要能力 **自建 held-out**。

**线上**  
A/B、人工抽检、**任务成功率**、安全拦截率；长文能力另加 **needle、多跳** 等专测（与 `**13`** 结合）。

### 面试口述

「PPL 看建模；榜作参考防污染；上线看业务指标与私有集。」

## 本篇小结

- **外推** = `L_infer > L_train`；坏因 = **RoPE 相位/相对距离 OOD** + 长序列注意力 + KV/数值工程。  
- **救法** = 位置插值、NTK/YaRN 类频率修正，常要 **长文微调**；RoPE 本体在 `**02` §7**。  
- **量化** = bit 换显存/速度；outlier 与 **GPTQ/AWQ/SmoothQuant** 三条误差分配。  
- **评测** = PPL + 榜 + 线上，不单指标决策。
