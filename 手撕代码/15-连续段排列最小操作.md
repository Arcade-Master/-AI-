# 15｜连续段排列最小操作

**标签**：贪心 / 排序 / 枚举  
**来源**：截图题  
**难度**：中等  
**状态**：可背

---

## 题面

给定长 n 的整数数组 a。先选一个整数 x（全程不变），再通过若干次操作把 a 变成区间 `[x, x+n-1]` 上每个整数**恰好出现一次**的排列（顺序任意）。

单次操作三选一（计 1 次）：

1. 某元素 +1；
2. 某元素 -1；
3. 若某元素已在 `[x, x+n-1]` 内，可一次改成该区间内**任意**整数。

求最优 x 下的最少操作次数；已经满足则输出 0。

---

## 思路

**一句话**：把 n 个数**分配**到目标集合 `{x,…,x+n-1}`（与数组下标顺序无关）；排序后第 i 小的配目标 `x+i` 最优；枚举候选 x 取最小代价。

### 1. 单个元素 v 落到目标 t 的代价

- **已在区间内** `x <= v <= x+n-1`：若 `v == t` 代价 0，否则用操作 3 跳过去，代价 1。
- **在区间左侧** `v < x`：先加减进到左端点 x，代价 `x-v`；若 `t == x` 不再跳，否则 +1。
- **在区间右侧** `v > x+n-1`：先进右端点 `x+n-1`，代价 `v-(x+n-1)`；若 `t == x+n-1` 不再跳，否则 +1。

### 2. 怎么配对

最终数组**怎么排都行**，但要决定「哪个原值变成哪个目标数」——这是**匹配**，不是按原下标一一对应。

排序 `sa[0] <= ... <= sa[n-1]`，让 `sa[i]` 匹配 `t_i = x+i`（第 i 小的原值 → 第 i 小的目标）。  
**不会交叉更优**：若 `sa[i] < sa[k]` 却让小的去大的目标，只会多付跳转或进区间的代价（交换论证）。

### 3. 枚举 x

`x` 的有效范围约为 `[min(a)-n+1, max(a)]`。  
代价只在 `x = sa[j] - i`（某个目标 `x+i` 正好对齐某个 `sa[j]`）处跳变，因此枚举全部 **n^2** 个候选 `{ sa[j]-i | 0<=i,j<n }`，每个 O(n) 评估取 min。

**复杂度**：时间 O(n^3) 最坏；n 较小时足够，大规模可改滑动窗口 O(n^2)。

**易错点**：

- 操作 3 只在**已进入区间后**才能用，区间外的元素不能一步跳到内部任意值；
- 右端点匹配条件是 `t == x+n-1`，不是 `x+n`；
- 排序后按**值的大小**配对，不是按原数组下标；
- 只枚举 `x=sa[i]-i` 共 n 个**不够**（会漏最优 x），必须枚举 `sa[j]-i`。

---

## 参考实现

```python
def min_ops(a: list[int]) -> int:
    n = len(a)
    sa = sorted(a)

    def cost(x: int) -> int:
        total = 0
        for i in range(n):
            v, t = sa[i], x + i
            if v < x:
                total += x - v + (0 if t == x else 1)
            elif v > x + n - 1:
                total += v - (x + n - 1) + (0 if t == x + n - 1 else 1)
            else:
                total += 0 if v == t else 1
        return total

    # 候选 x = sa[j]-i：目标 x+i 与 sa[j] 对齐的所有断点
    cands = {sa[j] - i for i in range(n) for j in range(n)}
    return min(cost(x) for x in cands)


def main() -> None:
    n = int(input())
    a = list(map(int, input().split()))
    print(min_ops(a))


if __name__ == "__main__":
    main()
```

---

## 变体 / 追问

- 若只能 +1/-1、没有区间跳转：变成排序后 L1 匹配，总代价 `sum |sa[i]-(x+i)|`。
- x 固定时能否 O(n) 滑动窗口维护代价：可以，但面试写候选枚举更稳。
